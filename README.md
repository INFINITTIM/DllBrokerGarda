# Message Broker (RPC)

Лёгкая C++ библиотека для организации синхронного RPC-взаимодействия (Remote Procedure Call) между модулями внутри одного процесса. Реализует паттерн централизованного брокера запросов с сериализацией и типизацией используемых операций.

## Компоненты

### Message (`include/Message.hpp`)

Базовый контейнер для передачи данных.

| Поле / Тип | Тип данных | Описание |
|------------|------------|----------|
| `payload` | `std::vector<uint8_t>` | Динамический буфер с сырыми байтами запроса или ответа. Автоматически освобождается при выходе из области видимости. |
| `TFuncOpReq` | `std::function<std::unique_ptr<Message>(const Message&)>` | Сигнатура обработчика операции: принимает запрос, возвращает умный указатель на ответ. |

### Manager (`include/Manager.hpp`, `src/Manager.cpp`)

Центральный маршрутизатор (Broker). Хранит таблицу соответствия `op_id → обработчик` и обеспечивает синхронную доставку запросов.

| Метод | Параметры | Описание |
|-------|-----------|----------|
| `provide` | `uint32_t op_id`, `TFuncOpReq handler` | Регистрирует функцию-обработчик для указанного кода операции. Перезаписывает существующий обработчик, если `op_id` уже занят. Возвращает `false` при передаче `nullptr`. |
| `request` | `uint32_t op_id`, `const Message& msg` | Выполняет синхронный поиск обработчика по `op_id`, вызывает его с переданным сообщением и возвращает результат. Возвращает `nullptr`, если операция не зарегистрирована. |

### Arithmetic (`include/Arithmetic.hpp`)

Эталонная реализация клиент-серверного взаимодействия на примере арифметических операций. Демонстрирует простую сериализацию через `memcpy` (возможно стоит переписать на какую-то более эффективную или используемую серилизацию (возможно из какой-то библиотеки если это требуется)) и обработку ошибок через `std::optional`.

#### Классы взаимодействия

| Класс | Назначение | Публичные методы |
|-------|------------|------------------|
| `ArithmeticServer` | Автоматически регистрирует обработчики `Add` и `Sub` в брокере при инициализации. Не хранит состояние между вызовами. | Конструктор: `explicit ArithmeticServer(Manager* broker)` |
| `ArithmeticClient` | Инкапсулирует логику сериализации запроса, отправки через брокер и десериализации ответа. | `std::optional<int64_t> add(int64_t lh, int64_t rh)`<br>`std::optional<int64_t> sub(int64_t lh, int64_t rh)` |

#### Структуры данных операций

| Структура | Поля | Описание |
|-----------|------|----------|
| `ArithmeticAddOpReq` | `int64_t lh`, `int64_t rh` | Запрос на сложение: левый и правый операнды |
| `ArithmeticAddOpResp` | `int64_t sum` | Ответ на сложение: результат операции |
| `ArithmeticSubOpReq` | `int64_t lh`, `int64_t rh` | Запрос на вычитание: уменьшаемое и вычитаемое |
| `ArithmeticSubOpResp` | `int64_t diff` | Ответ на вычитание: разность операндов |

#### Идентификаторы операций

| Константа / Enum | Значение | Описание |
|------------------|----------|----------|
| `kArithmStart` | `500` | Базовый индекс для арифметических операций (избегает пересечения с системными кодами) |
| `ArithmOp::Add` | `500` | Код операции сложения |
| `ArithmOp::Sub` | `501` | Код операции вычитания |

## Принцип работы

### Пошаговый поток выполнения запроса
1. **Инициализация**: Создаётся `Manager`. Вызывается `broker.start()`, переводящий брокер в активное состояние.
2. **Регистрация**: Конструктор `ArithmeticServer` вызывает `broker.provide(500, handler)` и `broker.provide(501, handler)`. Брокер сохраняет лямбда-функции в `std::unordered_map<uint32_t, TFuncOpReq>`.
3. **Формирование запроса**: Клиент создаёт структуру (например, `AddReq{10, 4}`), копирует её в `Message::payload` через `std::memcpy` и вызывает `broker.request(500, msg)`.
4. **Маршрутизация**: Брокер ищет `500` в таблице. При успехе вызывает сохранённую лямбду, передавая ей `Message`.
5. **Обработка**: Лямбда десериализует `payload` обратно в структуру, выполняет бизнес-логику (`lh + rh`), упаковывает результат в новый `Message` и возвращает `std::unique_ptr<Message>`.
6. **Возврат результата**: Брокер передаёт указатель клиенту. Клиент десериализует ответ, извлекает значение и возвращает его через `std::optional<int64_t>`.

## Управление жизненным циклом (START/STOP)

Брокер реализует конечный автомат состояния:
- **`start()`**: Инициализирует рабочее состояние. Без вызова этого метода система остаётся в режиме "ожидания", что позволяет безопасно загружать конфигурации перед приёмом запросов.
- **`stop()`**: Выполняет корректное завершение. Очищает таблицу обработчиков (`handlers_.clear()`), переводит флаг `running_` в `false` и гарантирует, что новые запросы будут отклонены (`request` вернёт `nullptr`).
