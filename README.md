# Message Broker (RPC)

Лёгкая C++ библиотека для организации синхронного RPC-взаимодействия (Remote Procedure Call) между модулями. Реализует паттерн централизованного брокера с абстракцией транспортного уровня, безопасным управлением памятью (RAII) и контролем жизненного цикла.

## Компоненты

### Message (`include/Message.hpp`)

Базовый контейнер для передачи данных. Использует RAII для автоматического освобождения памяти.

| Поле / Тип | Тип данных | Описание |
|------------|------------|----------|
| `payload` | `std::vector<uint8_t>` | Динамический буфер с сырыми байтами запроса или ответа. |
| `TFuncOpReq` | `std::function<...>` | Сигнатура обработчика операции: принимает `Message`, возвращает `unique_ptr<Message>`. |

### Manager (`include/Manager.hpp`, `src/Manager.cpp`)

Центральный контроллер. Делегирует фактическую доставку сообщений транспортному слою и управляет состоянием системы.

| Метод | Параметры | Описание |
|-------|-----------|----------|
| `start` | — | Активирует брокер. Переводит систему в рабочее состояние (`running_ = true`). |
| `stop` | — | Приостанавливает обработку запросов (`running_ = false`). **Не очищает таблицу обработчиков**, позволяя системе быстро возобновить работу. |
| `is_running` | — | Возвращает текущее состояние системы. |
| `provide` | `op_id`, `handler` | Регистрирует обработчик в транспортном слое. Доступно в любом состоянии системы. |
| `request` | `op_id`, `msg` | Отправляет запрос. Блокируется, если брокер остановлен (`stop()`), пока `start()` не будет вызван снова. |

### Arithmetic (`include/Arithmetic.hpp`)

Реализация бизнес-логики (клиент-сервер).

| Класс | Назначение | Публичные методы |
|-------|------------|------------------|
| `ArithmeticServer` | Регистрирует логику операций (`Add`, `Sub`) в брокере при инициализации. | `explicit ArithmeticServer(Manager* broker)` |
| `ArithmeticClient` | Отправляет запросы и десериализует ответы. Возвращает `std::optional`. | `add(a, b)`, `sub(a, b)` |

#### Идентификаторы операций
| Константа | Значение | Описание |
|-----------|----------|----------|
| `kArithmStart` | `500` | Базовый индекс для арифметики |
| `ArithmOp::Add` | `500` | Сложение |
| `ArithmOp::Sub` | `501` | Вычитание |

## Принцип работы

1. **Инициализация**: Создается `Manager` (по умолчанию с `LocalTransport`). Вызывается `broker.start()`.
2. **Регистрация**: `ArithmeticServer` вызывает `broker.provide()`, передавая лямбда-функции с логикой. Менеджер сохраняет их в транспортном слое.
3. **Запрос**: Клиент сериализует данные (`memcpy` -> `Message`) и вызывает `request()`.
4. **Транспорт**: Менеджер проверяет флаг `running_`. Если активно, передает управление `transport_->request()`, который находит и вызывает нужный обработчик.
5. **Ответ**: Результат десериализуется клиентом и возвращается через `std::optional`.

## Управление жизненным циклом (Pause / Resume)

Брокер реализует паттерн управления состоянием:
- **`start()`**: Открывает "клапан" для входящих запросов.
- **`stop()`**: Закрывает "клапан". Новые запросы отклоняются (`nullptr`), но **конфигурация системы (реестр обработчиков) сохраняется**.

## Архитектура (Транспортный уровень)

В системе выделен интерфейс `ITransport`.
- **`Manager`** отвечает за логику (включение/выключение, валидация).
- **`ITransport`** отвечает за доставку (поиск и вызов функции).
- **`LocalTransport`** (реализация по умолчанию) вызывает функции напрямую в памяти.
